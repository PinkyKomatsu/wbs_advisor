# WBS 項目判定アシスタント（医事会計システム更新）

医事会計システム更新プロジェクトの WBS（Excel）について、**大本のWBSひな形**と、そこから項目を転記して実際に使われた**実用WBS（過去事例）**を取り込み、今回の案件で必要な可能性が高い項目を判定・提示します。確定した項目は、**実用WBSと完全に同じ様式（マクロを含む）**の新しいファイルに書き込みます。

- **完全オフライン**：HTTP 通信・自動更新・テレメトリは一切ありません。
- **インストール不要・管理者権限不要**：`WBSAdvisor.exe` を置くだけで動きます。データ・設定・ログは `%LOCALAPPDATA%\WBSAdvisor\` に保存します。
- **様式を崩さない**：出力は常にテンプレートのファイルコピーから作り、VBA・図形・ボタン・入力規則・シート保護・印刷設定・条件付き書式などをそのまま保持します。書き込み後に自動で検証します。
- **日英の文章**：項目名と判定理由を日本語・英語の両方で作り、それぞれ別々にコピーできます。

## 1. 使い方

画面は 7 つのタブに分かれています。上から順に進めます。

### 1. 様式登録

- **ひな形**タブ：［ひな形（全作業項目のマスタ）を登録…］で、大本の WBS（.xlsx / .xlsm）を選びます。
- **実用WBS様式（出力テンプレート）**タブ：新しいファイルの元にする実用WBSの様式を登録します。
- 登録すると、**様式プロファイル**（対象シート・ヘッダー行・データ開始行・各列の意味）を見出しから自動で推定します。
  - 確信度が閾値（初期値 0.7）未満のときや、候補が複数あるときは、黄色の注意書きが出ます。右のプレビューでセルをクリックし、［この行をヘッダー行に］［この行をデータ開始行に］［この列の意味にする］などで指定して、［プロファイルを保存］を押します。
  - 実用WBS様式は「データ終了行（明細の最終行）」も推定します。合計行があれば、その手前までを明細とみなします。
- 実用WBS様式は、書き込み時の保護に使う情報を解析して表示します：数式セル、結合セル、入力規則（プルダウンの許可値）、シート保護とロックされていないセル、名前定義、VBA の有無、図形・フォームコントロール・ActiveX、リボン設定、条件付き書式。
- ひな形を登録すると、全項目名が用語辞書に登録されます（英語は空欄）。

### 2. 過去事例管理

- 実用WBSを画面上部にドラッグ＆ドロップするか、［ファイルを追加…］で取り込みます（複数可）。登録済みの実用WBS様式のプロファイルで読み込みます。
- **同じファイルの二重取込**はファイルのハッシュで検出し、警告します（それでも取り込むこともできます）。
- 事例を選ぶと、**案件属性**（更新種別・病床規模・ベンダー名・連携システム・実施年度・自由タグ）を入力できます。すべて任意で、未入力でも判定できます。

### 3. 照合確認

実用WBSの各行を、ひな形の項目に次の順で対応付けます。

1. WBS 番号の一致（名称がかけ離れている場合は採用しません）
2. 同義語辞書（この画面で以前に選んだ対応付け）
3. 作業項目名の完全一致（全角半角・空白・記号を正規化して比較）
4. rapidfuzz による類似度：90 以上は自動確定、70〜90 は**確認待ち**、70 未満は**ひな形外の追加項目**

「確認待ち」タブで対応するひな形項目を選び、［選択を確定］を押します。選んだ結果は同義語辞書に保存され、次回以降は自動で確定します。「ひな形外の追加項目」タブでは、実用WBSで独自に追加された項目を確認できます。

### 4. 条件ルール管理

「属性・演算子・値 → 対象項目を 必要／要検討／不要 にする」ルールを作ります。

- 例：連携システム **含む** PACS → 「PACS連携テスト」を**必要**
- 条件は複数設定でき、すべて満たしたときに適用します。演算子は ＝・≠・含む・含まない・以上・以下・入力あり・未入力。
- 対象項目は一覧から選ぶか、「項目名に含む語」で指定します。
- 有効／無効と優先順位（小さいほど優先）を設定できます。ルールは統計判定より優先し、適用したルール名が判定理由に表示されます。

### 5. 判定結果

1. 上部に**今回の案件の属性**を入力し（任意）、［判定を実行］を押します。
2. ひな形の各項目について、次を一覧表示します。
   - 採用率（採用した事例数 ÷ 対象事例数）と、属性が近い事例の重みを上げた**加重採用率**（「属性が近い事例の重みを上げる」で ON/OFF）
   - 判定：採用率 70% 以上＝**必要**、30% 未満＝**不要**、その間＝**要検討**（閾値は設定で変更）
   - 適用したルール、採用した事例・採用しなかった事例
   - 子の項目が採用されていれば親の項目も採用とみなします。ひな形外の追加項目も候補として並びます。
3. 「判定」のプルダウンで**手動で上書き**できます。理由を入力でき、上書きの履歴が残ります。手動上書きはルールより優先します。
4. 「出力」のチェックで出力する項目を確定します。初期状態は「必要」の項目にチェックが入っています。
5. 下部の**日本語エリア**と**英語エリア**に、項目名と判定理由が表示されます。
   - 例：「過去8件中7件（88%）で採用。条件『PACS連携あり』に一致。」／ "Adopted in 7 of 8 past projects (88%). Matches condition: PACS integration."
   - ［日本語をコピー］［英語をコピー］で、それぞれ別々にクリップボードへコピーします。範囲（全項目／選択行のみ）と形式（タブ区切り＝Excel にそのまま貼付／改行区切りテキスト）を選べます。
   - 用語辞書にない語は英文中に【未翻訳: ○○】と表示し、件数を警告します。「7. 設定」の用語辞書で英語を登録してから判定し直してください。

### 6. Excel出力

1. 上部に、Excel の有無と自動で選ばれた**書き込み方式**が表示されます（切り替えも可）。
   - **Excel COM 方式**（Excel がある PC の既定）：不可視の Excel を新しく起動し、マクロ・イベントを無効にしてから書き込みます。空き行が足りないときは、直上行の書式・入力規則・数式をコピーして行を挿入します。
   - **OOXML 直接編集方式**（Excel がない PC）：ファイルの中の対象シートの値だけを書き換えます。行の挿入には対応しないため、空き行が足りないときは書き込まずに不足行数を知らせます。
2. 左の表で、テンプレートの各列に**ひな形のどの列の値を書くか**を確認します。同じ意味の列は自動で対応付き、判断できない列は黄色で表示されるので選んでください。［列の対応を様式プロファイルに保存］で次回以降も使います。
3. ［差分プレビューを作成］で、どのセルに何を書くか（書かないセルとその理由）を確認します。「テンプレートのプレビュー」タブでは書き込むセルがオレンジで表示され、開始行や明細の最終行に迷う場合はセルをクリックして指定できます（様式プロファイルに保存されます）。
4. ［確認して出力］を押すと、`テンプレート名_YYYYMMDD_HHMMSS.xlsm`（元と同じ拡張子）として保存します。テンプレートは上書きしません。保存先は既定で `%LOCALAPPDATA%\WBSAdvisor\output\` です（［出力フォルダを開く］で開けます）。
5. 出力後、**検証結果**タブにテンプレートとの比較結果が表示されます：vbaProject.bin、図形・画像、フォームコントロール、ActiveX、名前定義、結合セル、入力規則、条件付き書式、シート保護、印刷設定、列幅、書式、書き込んだ値。

**書き込みの共通ルール**

- 結合セルは左上のセルにだけ書き込みます。
- 入力規則（プルダウン）のあるセルには許可値だけを書き込みます。許可値にない値は「値の対応表」（例：病院 → 病院情報システム部）で置き換え、それでも許可値にならなければ書き込まずに警告します。
- 数式セル・（シート保護時の）ロックされたセルには書き込みません。明細に数式がある列（例：No＝`=ROW()-4`）は、既定で書き込み対象から外します。
- 書式（フォント・罫線・塗り・表示形式・列幅・行高）は変更しません。
- テンプレートの明細に残っている値は、書き込む前に消去します（数式・ロックされたセルは除く。設定で変更可）。

### 7. 設定

- 判定の閾値（必要・不要）、照合の閾値（自動確定・確認待ち）、重み付けの ON/OFF と強さ、病床規模の区分、属性の選択肢、書き込み方式
- **値の対応表**：列の意味ごと（* はすべての列）に「元の値 → 書き込む値」
- **用語辞書**：日本語 → 英語。検索、英語が空欄の語だけの表示、CSV（日本語,英語）のインポート・エクスポート
- **定型文テンプレート**：判定理由の日英の文。`{total}` `{adopted}` `{rate}` `{wrate}` `{rule}` `{decision}` を差し込めます

## 2. 配布（管理者権限なし）と警告が出たときの対処

### 配布

1. `dist\WBSAdvisor.exe`（単一ファイル）を、利用者の PC の任意のフォルダ（デスクトップ、ドキュメント、共有フォルダなど）にコピーします。インストーラーはありません。
2. ダブルクリックで起動します。管理者権限は不要です。
   - データ・設定・ログは `%LOCALAPPDATA%\WBSAdvisor\`（例：`C:\Users\<ユーザー名>\AppData\Local\WBSAdvisor\`）に作られます。exe の置き場所が書込不可でも動きます。
   - レジストリの HKLM や Program Files には書き込みません。
   - 単一 exe のため、起動時に一時フォルダ（`%TEMP%\_MEI…`）へ展開します。初回の起動は数秒かかります。
3. アンインストールは、exe と `%LOCALAPPDATA%\WBSAdvisor\` フォルダを削除するだけです。

### Windows SmartScreen の警告が出たとき

署名のない exe のため、「Windows によって PC が保護されました」と表示されることがあります。

- 配布元が確かな場合は、［詳細情報］→［実行］で起動できます。
- 組織で SmartScreen の回避が禁止されている場合は、情報システム部門に次を伝えて許可を依頼してください。
  - ファイル名と SHA-256 ハッシュ（PowerShell で `Get-FileHash .\WBSAdvisor.exe -Algorithm SHA256`）
  - 用途（オフラインで動作し、外部通信を行わない社内ツールであること）
- 恒久的には、組織のコード署名証明書で exe に署名するのが確実です（`signtool sign /fd SHA256 /a WBSAdvisor.exe` など）。

### ウイルス対策ソフトに誤検知されたとき

PyInstaller で作った単一 exe は、起動時に自分自身を展開する動きのため、誤って検知されることがあります。

1. 検知された場合は、自分で除外設定をせず、情報システム部門に**除外申請**してください。申請時は上記の SHA-256 ハッシュ、ファイルの配置場所、用途を伝えます。
2. 誤検知としてベンダーに報告する（各ウイルス対策ソフトの誤検知報告窓口）と、次の定義ファイルで解消されることがあります。
3. 社内で配布する場合は、ソースからビルドした exe（ハッシュを記録）を 1 か所に置き、そのハッシュを除外申請に使うと管理しやすくなります。

## 3. 開発環境（VS Code）

### 必要なもの

- Windows 11 64bit、Python **3.12**、VS Code（拡張機能「Python」）
- Excel（COM 方式とそのテストに使用。なくても OOXML 方式で動きます）

### 環境構築

```bat
cd wbs_advisor
rem uv を使う場合
uv python install 3.12
uv venv --python 3.12 .venv
uv pip install --python .venv\Scripts\python.exe -r requirements.txt
rem uv を使わない場合
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

VS Code では、コマンドパレットの「Python: Select Interpreter」で `.venv\Scripts\python.exe` を選びます。

### 実行

```bat
.venv\Scripts\python main.py
```

開発中のデータも `%LOCALAPPDATA%\WBSAdvisor\` に保存されます。環境変数 `WBSADVISOR_HOME` で保存先を変えられます。

### テスト

```bat
.venv\Scripts\python -m pytest -v
```

| ファイル | 内容 |
| --- | --- |
| `tests/test_core.py` | 正規化、照合（WBS 番号・名称・類似度・同義語辞書・ひな形外）、採用率、閾値判定、親子の採用、加重採用率、ユーザールールの優先と演算子、手動上書きと履歴、日英テンプレート（仕様の例文そのもの）、未翻訳語の検出、コピー形式、ひな形 1000 行・過去事例 50 件の性能 |
| `tests/test_excel.py` | 様式プロファイルの推定、確信度が低い場合、様式の解析（拡張領域の入力規則を含む）、書き込みの共通ルール（数式・結合・入力規則・値の対応表）、**OOXML 方式・COM 方式それぞれで vbaProject.bin の一致・図形とボタンの存在・結合セル・入力規則・書式が保持されること**、行挿入（数式・入力規則・合計範囲）、マクロが実行されないこと、シート保護（ロックされたセル・行挿入の拒否）、Excel で開いて修復が出ないこと、Excel プロセスが残らないこと |

COM 方式のテストは Excel がない PC では自動でスキップします。

**テスト用ファイル（fixtures）**：`tests/fixtures/` に、ダミーのひな形・実用WBS 3 件・マクロ付きテンプレート（標準モジュール＋ボタン＋図形、保護付きの版も）を同梱しています。作り直すときは次を実行します（Excel が必要）。

```bat
.venv\Scripts\python tests\fixtures\make_fixtures.py
```

マクロ付きの .xlsm をプログラムで作るため、実行中だけ HKCU の「VBA プロジェクト オブジェクト モデルへのアクセスを信頼する」（`AccessVBOM`）を 1 にし、Excel が完全に終了してから元の値に戻します（Excel 2013 は終了時にこの設定を書き戻すため）。レジストリのキーは Excel のバージョン（15.0＝Excel 2013、16.0＝2016 以降）に合わせます。

### ビルド

```bat
.venv\Scripts\python -m PyInstaller --noconfirm --clean build.spec
```

`dist\WBSAdvisor.exe`（単一ファイル、ウィンドウアプリ）ができます。

### 自己診断

画面を自動で操作して「様式登録 → 事例取込 → 照合 → 判定 → コピー → 出力 → 検証」を一通り行い、結果と画面の画像を保存します。

```bat
WBSAdvisor.exe --selftest C:\temp\diag --fixtures <wbs_advisor>\tests\fixtures
```

結果は `C:\temp\diag\selftest.json` に書かれます。自己診断のデータは出力先の中に作るので、`%LOCALAPPDATA%\WBSAdvisor\` は変わりません。

## 4. 設計概要

### モジュール構成

```
wbs_advisor/
  main.py                 起動・ログ・例外処理・自己診断
  app/                    GUI（PySide6）
    main_window.py        7 つのタブと進捗バー
    widgets.py            アプリの状態・QThread ワーカー・例外表示・プレビューグリッド・案件属性の入力欄
    pages/                format_page（様式登録）・cases_page（過去事例）・matching_page（照合確認）・
                          rules_page（条件ルール）・judgment_page（判定結果）・export_page（Excel出力）・settings_page（設定）
  core/                   照合・判定・ルール・文章生成（GUI・Excel に依存しない）
    normalize.py          全角半角・空白・記号の正規化、WBS 番号の正規化
    matching.py           WBS 番号 → 同義語辞書 → 完全一致 → rapidfuzz の照合
    judgment.py           採用率・加重採用率・閾値判定・ルール・手動上書き・出力順
    texts.py              用語辞書による英訳・未翻訳語の検出・日英の定型文・コピー用の文字列
    workflow.py           画面から使う一連の処理
    db.py / config.py / paths.py / models.py
  excel_io/               Excel
    reader.py             openpyxl による読込（read_only と通常モードを使い分け）
    profile.py            様式プロファイルの推定
    inspect.py            様式の解析（数式・結合・入力規則・保護・名前・VBA・図形・コントロール）
    plan.py               書き込み計画（差分プレビューと共通ルール）
    com_writer.py         Excel COM 方式
    ooxml_writer.py       OOXML 直接編集方式（lxml）
    engine.py             方式の選択・出力ファイル名
    verify.py             書き込み後の検証
  resources/              初期設定（default_config.json）・定型文テンプレート（text_templates.json）
  tests/                  pytest ＋ fixtures
  build.spec  requirements.txt  pytest.ini
```

### データベース（SQLite：`%LOCALAPPDATA%\WBSAdvisor\wbs.db`）

| テーブル | 内容 |
| --- | --- |
| `formats` | 登録した様式（kind＝master：ひな形／output：実用WBS様式）。ファイルのコピーの場所・ハッシュ・プロファイル（JSON）・解析結果（JSON） |
| `master_items` | ひな形の項目。`item_key`（工程＋名称を正規化した識別子。ひな形を登録し直しても同じ項目なら同じ値）・WBS 番号・階層・親・各列の値 |
| `cases` | 過去事例。ファイルの SHA-256（二重取込の検出）・案件属性（JSON） |
| `case_rows` | 過去事例の各行と、ひな形項目への対応付け（方法・類似度・状態・候補・直前の項目） |
| `synonyms` | 照合確認で選んだ対応付け（正規化した名称 → item_key） |
| `rules` | ユーザー独自条件（条件・判定・対象・優先順位・有効） |
| `project` | 今回の案件の属性 |
| `overrides` | 手動上書きの履歴（項目ごとに最新の 1 件が有効） |
| `glossary` | 用語辞書（日本語 → 英語） |

設定は `%LOCALAPPDATA%\WBSAdvisor\config.json`（初期値は `resources/default_config.json`）、定型文は `text_templates.json`、ログは `logs\app.log` です。**ログにはセルの内容を書きません**（件数・処理名・エラーの種類と場所のみ）。

### 画面の流れ

```
1. 様式登録 ──→ 2. 過去事例管理 ──→ 3. 照合確認 ──→ 5. 判定結果 ──→ 6. Excel出力
   （ひな形・実用WBS様式）  （取込・属性）   （確認待ちの選択）   ↑（属性入力・判定・上書き・日英コピー）
                                              4. 条件ルール管理 ─┘
7. 設定（閾値・値の対応表・用語辞書・定型文）はいつでも
```

重い処理（事例の取込・判定・出力）は QThread で実行し、ステータスバーの進捗バーに進み具合を表示します。例外はすべて捕捉し、日本語のメッセージを表示します。

## 6. 制限事項・困ったとき

| 症状・制限 | 対処 |
| --- | --- |
| `.xls` を登録・取込できない | Excel で .xlsx または .xlsm として保存し直してください |
| 様式の自動推定がずれる | 「1. 様式登録」のプレビューでヘッダー行・データ行・列の意味を指定し、［プロファイルを保存］ |
| 出力で「空き行が不足」と出る（OOXML 方式） | Excel がインストールされた PC で出力するか、テンプレートの空き行を増やしてください |
| 出力で「保護されているため行を挿入できません」 | テンプレートのシート保護を解除するか、空き行を増やしてください |
| 入力規則の許可値にない値が書かれない | 「7. 設定」の値の対応表に置き換えを登録してください。差分プレビューと警告に、書かなかったセルと理由が出ます |
| 英文に【未翻訳: …】が出る | 「7. 設定」の用語辞書で英語を登録し、判定をやり直してください |
| 保存できない | 同じ名前のファイルを Excel で開いていないか確認してください |
| エラーの詳細 | `%LOCALAPPDATA%\WBSAdvisor\logs\app.log`（セルの内容は記録しません） |
